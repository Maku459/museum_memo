# museum_memo

博物館で撮った「展示物の写真」と「解説文の写真」をまとめてアップロードすると、
解説文をOCRで読み取り、撮影時刻を手がかりに展示物の写真を差し込んだ
**Markdownの見学メモ**を組み立てるWebアプリです。

画像の読み込み・OCR・Markdownの生成はすべてブラウザ内で完結します。
写真がサーバーへ送られることはありません（OCRの言語データを取得するときだけ外部へ通信します）。

## できること

- 写真をまとめてドロップ → 撮影日時（EXIF `DateTimeOriginal`）順に自動で整列
- 解説パネルの写真は **OCR（日本語＋英語）** で読み取り、本文を**省略せず全文**メモに入れる
- 展示物の写真は、いちばん近い解説文の**前後どちらで撮ったか**を見て、その位置に差し込む
- 判定を間違えたときは、写真ごとに「解説文／展示物」を手で切り替え可能
- OCRの誤字はその場で修正でき、直した内容がすぐMarkdownに反映される
- 出力は「クリップボードにコピー」「`.md`を保存」「ZIP（`.md` + 画像フォルダ）」から選べる

## 使い方

```bash
npm install
npm run dev     # http://localhost:5173/
```

本番用のビルドは `npm run build`（出力は `dist/`）、確認は `npm run preview` です。
`base` は相対パスにしてあるので、`dist/` をそのまま静的ホスティングやサブディレクトリに置けます。

## まとめ方の仕組み

1. **撮影時刻を読む** — EXIFの `DateTimeOriginal` を使います。EXIFが無い画像はファイルの更新日時で代用し、
   画面上の「撮影日時」欄から手で直せます。
2. **種別を判定する** — OCRで読み取れた文字数がしきい値（既定30字）以上なら解説パネル、
   それ未満なら展示物とみなします。読み取りの信頼度が低く短いものは展示物側に倒します。
3. **項目にまとめる** — 展示物の写真は、時間がいちばん近い解説文に紐づけます
   （既定で前後5分以内。離れているものは「展示物（解説なし）」としてまとめます）。
4. **Markdownを組む** — 解説文より前に撮った展示物写真は本文の前、後に撮ったものは本文の後ろに置きます。

出力はこのような形になります。

```markdown
# 博物館 見学メモ

- 訪問日: 2026-05-03（10:00〜10:40）
- 写真: 3枚（解説文 1枚 / 展示物 2枚）
- 項目: 2件

---

## 1. 火焔型土器

*2026-05-03 10:00*

![火焔型土器](images/exhibit-a.jpg)
*10:00 撮影 — exhibit-a.jpg*

火焔型土器
新潟県笹山遺跡から出土した縄文中期の土器である。……（解説文の全文）

*OCR: panel-a.jpg（信頼度 87%）*
```

### 設定できること（画面の「まとめ方の設定」）

| 設定 | 既定 | 内容 |
| --- | --- | --- |
| メモのタイトル | 博物館 見学メモ | 見出しと保存ファイル名になります |
| 展示物を解説文に紐づける時間差 | 5分 | 広げると1項目にまとまりやすくなります |
| 解説文とみなす文字数 | 30字 | 展示物のキャプションが写り込むときは大きめに |
| 画像の埋め込み方 | 相対パス参照 | `data:` URLでの直接埋め込みにすると`.md`1枚で完結します |
| 撮影時刻 / OCRの補足情報 / 解説パネルの写真 | — | メモに載せるかどうか |

## OCRについて

OCRは [tesseract.js](https://github.com/naptha/tesseract.js)（`jpn+eng`）をブラウザ内で動かしています。
既定ではワーカー・wasm・言語データをCDNから取得するため、**初回の読み取りだけ時間がかかります**。

外部への接続が制限された環境では、次の手順で手元に配置できます。

```bash
npm run vendor:tesseract                       # worker と wasm を public/tesseract/ にコピー
mkdir -p public/tessdata
curl -L -o public/tessdata/jpn.traineddata.gz https://tessdata.projectnaptha.com/4.0.0/jpn.traineddata.gz
curl -L -o public/tessdata/eng.traineddata.gz https://tessdata.projectnaptha.com/4.0.0/eng.traineddata.gz
cp .env.example .env                           # 各パスの行のコメントを外す
```

OCRエンジンを用意できなかった場合は、その旨を画面に表示したうえで
**解説文を手入力できる欄**を出します。手入力した文章もOCR結果と同じようにまとめられます。

## 制限と注意点

- OCRの精度は写真の写り方に左右されます。明るく、正面から、パネル全体が入るように撮ると読み取りやすくなります。
- HEIC/HEIFはブラウザが表示・デコードできないことがあります。JPEGやPNGでの取り込みを推奨します。
- EXIFの撮影日時が無い写真（スクリーンショットや加工済み画像など）は並び順がずれることがあるため、
  画面上で撮影日時を直してください。
- ZIPには読み込んだ写真をすべて同梱します（Markdownから参照していない解説パネルの写真も含みます）。

## 構成

```
src/
  App.tsx              画面全体の状態管理（取り込み・OCR実行・書き出し）
  types.ts             Photo / Section / 設定の型
  components/          写真カード・設定パネル・組み立て結果の確認パネル
  lib/
    image.ts           EXIFの読み取りと画像の縮小
    ocr.ts             tesseract.jsのワーカー管理（1件ずつ順番に処理）
    text.ts            OCR結果の整形・見出し抽出・Markdownのエスケープ
    group.ts           種別の判定と、撮影時刻にもとづく項目分け
    markdown.ts        Markdownの組み立て
    download.ts        .md / ZIP の保存
scripts/
  vendor-tesseract.mjs OCRの実行ファイルを public/ に配置する
```
