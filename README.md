# museum_memo

博物館で撮った「展示物の写真」と「解説文の写真」をまとめてアップロードし、
解説パネルの写真を選ぶと、その文字をGoogle Cloud Visionで読み取り、
撮影時刻を手がかりに展示物の写真を差し込んだ**Markdownの見学メモ**を組み立てるWebアプリです。

外へ送られるのは**解説文に指定した写真だけ**です。展示物の写真はブラウザから出ず、
並べ替えもMarkdownの組み立てもすべて手元で行います。

## できること

- 写真をまとめてドロップ → 撮影日時（EXIF `DateTimeOriginal`）順に自動で整列
- 解説パネルの写真を選ぶと **Cloud Vision（`DOCUMENT_TEXT_DETECTION`）** で読み取り、本文を**省略せず全文**メモに入れる
- 展示物の写真は読み取らない。いちばん近い解説文の**前後どちらで撮ったか**を見て、その位置に差し込む
- 読み取りの誤字はその場で修正でき、直した内容がすぐMarkdownに反映される
- 読み取らずに解説文を直接入力してもよい（キーを使いたくないときや、うまく読めなかったとき）
- 出力は「クリップボードにコピー」「`.md`を保存」「ZIP（`.md` + 画像フォルダ）」から選べる

## 使い方

```bash
npm install
npm run dev     # http://localhost:5173/
```

本番用のビルドは `npm run build`（出力は `dist/`）、確認は `npm run preview` です。
`base` は相対パスにしてあるので、`dist/` をそのまま静的ホスティングやサブディレクトリに置けます。

## スマホから使う

写真はスマホの中にあることが多いので、スマホのブラウザから開いて使うのが実用的です。画面は1カラムに切り替わります。

### 1. 公開して使う（おすすめ）

`main`へのpushで GitHub Pages に自動デプロイされます（`.github/workflows/deploy.yml`）。
初回だけ **Settings > Pages > Source** を **GitHub Actions** に変更してください。
公開後は `https://<ユーザー名>.github.io/museum_memo/` をスマホで開き、
Safari / Chromeの「ホーム画面に追加」でアプリのように起動できます。

URLは公開されますが、APIキーは各自のブラウザに保存されるものなので、
公開ページに他人のキーが載ることはありません。キーには必ずウェブサイト制限をかけてください。

### 2. その場でPCの開発サーバーにつなぐ

PCとスマホが同じWi-Fiにあれば、`npm run dev` が表示する `Network:` のURL
（`http://192.168.x.x:5173/`）をスマホのブラウザで開くだけです。設定は要りません。

### スマホで使うときの注意

- **写真の形式** — iPhoneの標準はHEICで、ブラウザによっては読み込めません。
  「設定 > カメラ > フォーマット」を**互換性優先**にしておくとJPEGで保存され、確実です。
- **通信** — 読み取りは解説パネル1枚ごとにVision APIを呼びます。枚数が多いときはWi-Fi環境をおすすめします。
- **保存はこまめに** — 読み込んだ写真はブラウザのメモリ上にしかありません。
  タブを閉じたり、他のアプリを長く使ってタブが破棄されると消えます。
- **書き出し** — iOSでは`.md`もZIPも「ファイル」アプリに保存され、そのまま他のアプリへ共有できます。
  Markdownをそのままメモアプリに貼るなら「コピー」が手軽です。

## まとめ方の仕組み

1. **撮影時刻を読む** — EXIFの `DateTimeOriginal` を使います。EXIFが無い画像はファイルの更新日時で代用し、
   画面上の「撮影日時」欄から手で直せます。
2. **解説パネルを選ぶ** — 取り込んだ写真はすべて展示物として扱われます。
   解説パネルの写真を「解説文」に切り替えると、その写真だけがVision APIに送られて読み取られます。
3. **項目にまとめる** — 展示物の写真は、時間がいちばん近い解説文に紐づけます
   （既定で前後5分以内。離れているものは「展示物（解説なし）」としてまとめます）。
4. **Markdownを組む** — 解説文より前に撮った展示物写真は本文の前、後に撮ったものは本文の後ろに置きます。

出力はこのような形になります。

```markdown
# 博物館 見学メモ

- 訪問日: 2026-05-03（10:00〜10:40）
- 写真: 3枚（解説文 1枚 / 展示物 2枚）
- 項目: 2件

---

## 1. 火焔型土器

*2026-05-03 10:00*

![火焔型土器](images/exhibit-a.jpg)
*10:00 撮影 — exhibit-a.jpg*

火焔型土器
新潟県笹山遺跡から出土した縄文中期の土器である。……（解説文の全文）

*読み取り: panel-a.jpg（信頼度 97%）*
```

### 設定できること（画面の「まとめ方の設定」）

| 設定 | 既定 | 内容 |
| --- | --- | --- |
| メモのタイトル | 博物館 見学メモ | 見出しと保存ファイル名になります |
| Vision APIキー | 未設定 | このブラウザにのみ保存されます |
| 展示物を解説文に紐づける時間差 | 5分 | 広げると1項目にまとまりやすくなります |
| 「。」が来るまで改行しない | オン | パネルの折り返しで切れた文を1文＝1行にまとめます |
| 画像の埋め込み方 | 相対パス参照 | `data:` URLでの直接埋め込みにすると`.md`1枚で完結します |
| 撮影時刻 / 読み取りの補足情報 / 解説パネルの写真 | — | メモに載せるかどうか |

## Cloud Vision APIの準備

読み取りには [Google Cloud Vision API](https://cloud.google.com/vision/docs/ocr) を使います。
サーバーを持たない構成のため、**APIキーは利用者が画面から入力し、そのブラウザのlocalStorageにだけ保存**します。
ビルドに埋め込むことはしません（公開サイトに置くとキーがそのまま漏れるためです）。

1. [Google Cloud コンソール](https://console.cloud.google.com/)でプロジェクトを作り、**Cloud Vision API を有効化**
2. 「APIとサービス > 認証情報」でAPIキーを作成
3. 作ったキーに次の制限をかける（**強く推奨**）
   - **APIの制限**: Cloud Vision API のみ
   - **アプリケーションの制限**: ウェブサイト → 使うページのURL（例 `https://<ユーザー名>.github.io/*`、ローカルで使うなら `http://localhost:5173/*`）
4. アプリの「まとめ方の設定」にキーを貼り付ける

### 料金

`DOCUMENT_TEXT_DETECTION` は**月1,000ユニットまで無料**、超過分は1,000枚あたり$1.50です
（2026年8月時点。最新は[料金表](https://cloud.google.com/vision/pricing)を確認してください）。
このアプリが送信するのは解説パネルとして選んだ写真だけなので、個人の見学メモであれば
無料枠に収まることがほとんどです。Google Cloudで予算アラートや割り当て上限も設定しておくと安心です。

### 読み取った文章の改行

パネルの文章は幅の都合で途中改行されているため、`fullTextAnnotation.text` をそのまま使うと
見た目の1行ごとに改行が入ってしまいます。そこで次の2段階で整えています。

1. Visionが返す行末（`EOL_SURE_SPACE`）と段落末（`LINE_BREAK`）の区別をたどり直し、
   **段落を1行**に組み直す（折り返しの改行を消す）
2. それでも文の途中で段落が分かれている場合に備え、**「。」などの文末が来るまで次の行をつなぐ**
   （設定で解除できます）

見出しが本文とくっつかないよう短い行はつなぎません。箇条書き・番号で始まる行も独立させます。
英文どうしをつなぐときだけ空白を入れ、日本語は詰めます。

### 注意

- APIキーをブラウザに置く以上、上記のキー制限は必ずかけてください。制限のないキーが漏れると第三者に使われます。
- 送信するのは長辺1800pxに縮小したJPEGです（通信量とコストを抑えるため）。
- 読み取りに失敗した場合や、キーを使いたくない場合は、解説文を直接入力しても同じようにまとめられます。

## 制限と注意点

- 読み取り精度は写真の写り方に左右されます。明るく、正面から、パネル全体が入るように撮ると読み取りやすくなります。
- HEIC/HEIFはブラウザが表示・デコードできないことがあります。JPEGやPNGでの取り込みを推奨します。
- EXIFの撮影日時が無い写真（スクリーンショットや加工済み画像など）は並び順がずれることがあるため、
  画面上で撮影日時を直してください。
- ZIPには読み込んだ写真をすべて同梱します（Markdownから参照していない解説パネルの写真も含みます）。

## 構成

```
src/
  App.tsx              画面全体の状態管理（取り込み・読み取り・書き出し）
  types.ts             Photo / Section / 設定の型
  components/          写真カード・設定パネル・組み立て結果の確認パネル
  lib/
    image.ts           EXIFの読み取りと画像の縮小
    vision.ts          Cloud Vision APIの呼び出しとAPIキーの保存
    text.ts            読み取り結果の整形・見出し抽出・Markdownのエスケープ
    group.ts           撮影時刻にもとづく項目分け
    markdown.ts        Markdownの組み立て
    download.ts        .md / ZIP の保存
```
